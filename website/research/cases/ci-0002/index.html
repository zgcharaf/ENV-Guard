Public case study · CI-0002 · November 9, 2026

A dependency conflict that stopped Python CI

An independently sourced failed build, its merged dependency correction, and a limited EnvGuard replay using public package metadata.

Abstract

Two CI jobs in the public zbase repository failed because a test dependency pinned pytest==9.0.3 while pytest-asyncio==1.2.0 required pytest below 9. The upstream project merged a one-line update to pytest-asyncio==1.4.0 and its following CI run passed. Independently, EnvGuard CI reproduced the minimal conflicting pair using pip's all-wheel, dry-run resolver, recognized DEPENDENCY_RESOLUTION_CONFLICT, and recorded successful resolution with the corrected pair. This is a transparent public development exemplar, not a blind field-accuracy trial.

1. Observations from the original CI failure

The source issue is cvsz/zbase #19. The reported revision used the following pinned test dependencies:

requirements-dev.txt, original revision (relevant lines)
pytest==9.0.3
pytest-asyncio==1.2.0

The original GitHub Actions workflow contained failures in lint and unit tests (job 128590526773) and integration, S3 compatibility and security (job 128590526601). The decoded pip logs contained an explicit dependency-resolution conflict:

Log evidence — condensed, not a full reproduced log

pytest-asyncio 1.2.0 required pytest<9, >=8.2, while the project pinned pytest==9.0.3. Pip reported ResolutionImpossible and exited nonzero.

These are observations about the original upstream CI, not an EnvGuard diagnosis of that historical job. The failed revision's dependency file supports the stated pins.

2. Correction verified in the upstream project

PR #24 was merged. Its visible diff changes one test dependency pin:

One-line source correction
-pytest-asyncio==1.2.0
+pytest-asyncio==1.4.0

The subsequent CI run completed successfully across its five reported jobs. The lint/unit log recorded 90 passed; the integration log recorded 199 passed, 1 warning. The fixed revision's dependency file contains the corrected pin.

Evidence strength. The original failure, merged change and following green CI are public primary records. This is stronger than an issue merely being closed. It still does not demonstrate that EnvGuard autonomously discovered the repair.

3. EnvGuard's hosted minimal-pair replay

The independent EnvGuard GitHub Actions workflow ran on Ubuntu 24.04 with Python 3.12. It requested public PyPI wheel metadata through pip's isolated, dry-run resolver. It did not clone, install or execute the upstream application.

4. Reproducing the experiment

From a local checkout, with a supported Python runtime and access to the public PyPI index:

Run the publicly defined minimal-pair experiment
python -m pip install -e .
python research/replay_public_conflict.py \
  --out research-results/public-replay
python research/validate_public_replay.py \
  --input research-results/public-replay/replay-summary.json

The script wraps pip with EnvGuard, preserves the command's actual exit code, writes detailed local reports and publishes only a bounded JSON summary without raw stdout/stderr. The resolver is configured with --dry-run, --ignore-installed, --only-binary=:all: and the public index. Network access to PyPI is necessary; no application dependency is installed by the resolver test.

5. Limits, causal interpretation and holdout exclusion

  1. Known solution. The authors inspected PR #24 before constructing this test. The case is consequently not blinded and cannot be used as evidence for independent attribution accuracy.
  2. Minimal-pair reduction. The replay resolves only the two conflicting package pins, not the full upstream dependency set or all CI jobs.
  3. Different execution context. The upstream CI and EnvGuard replay may differ in operating system, pip version, index metadata and other dependencies.
  4. No code execution from zbase. We deliberately did not execute the third-party application's tests, examine any private runner data or access non-public project resources.
  5. Not a competitor leaderboard. Pip already reports the conflicting constraints; EnvGuard adds a separate diagnostic summary. This experiment is not proof of superiority to pip or uv.

Research classification. Case CI-0002 has the status public_development_exemplar, with holdout_eligible=false in the curated source ledger. It must be excluded when an independent evaluation set is frozen.
