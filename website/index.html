Evidence before inference.

A practical method for investigating Python environment failures in continuous integration.

EnvGuard CI · Experimental release candidate · MIT License
Abstract

When Python works locally but fails in CI, an error message rarely explains its own cause. EnvGuard CI records runtime and interpreter evidence, compares compatible environments, and produces a human-readable incident dossier with explicit uncertainty. It complements existing package managers; it does not replace them.

01

Motivation

Consider a job that terminates with ModuleNotFoundError. The package may be undeclared, absent from the selected environment, or installed correctly in another interpreter. The observed exception is not sufficient to distinguish these explanations.

Our design principle is simple: every diagnosis should identify its evidence, explain its limits, and remain unresolved when the evidence does not suffice.

Working principle

A failing execution is an observation. An environmental difference is a correlation. A repair that passes a controlled retest provides stronger, but still bounded, evidence.

02

Method

(i)

Observe

Capture the executed Python runtime, installed distributions, project metadata, and the command outcome.

(ii)

Compare

Compare a failing snapshot with a compatible known-good environment, when one is available.

(iii)

Explain

Separate observed signatures, supporting evidence, possible causes, and recommended next checks.

04

Getting started

Install from the source repository. The release candidate is not represented here as a published PyPI package.

Terminal · Linux, macOS, or PowerShell
git clone https://github.com/zgcharaf/ENV-Guard.git
cd ENV-Guard
python -m pip install -e .
envguard-ci --version

Wrap an existing command and save an evidence report:

Terminal · evidence collection
envguard-ci investigate --project . \
  --snapshot-out current.json \
  --report-out incident.json \
  -- python -m pytest

The wrapped command executes with your current permissions and retains its exit status. For a complete guided setup, see Tutorial 1.

05

Scope & limitations

What the current release supports

  • Local environment snapshots and dependency inspection
  • Explicit interpreter provenance for directly invoked Python
  • GitLab and GitHub successful-baseline retrieval with appropriate access
  • JSON and Markdown incident reports
  • Wheel integrity inspection; bounded interpreter-candidate experiments

What it does not establish

  • Guaranteed causal explanation for arbitrary CI failures
  • Automatic remediation of applications or lockfiles
  • Tracing of shell wrappers and arbitrary child processes
  • Production compatibility from a single smoke test
  • A secure sandbox for untrusted code execution

See the security and trust model for operational precautions and the report interpretation guide for confidence semantics.
